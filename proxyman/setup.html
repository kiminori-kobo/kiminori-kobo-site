1. インストール（Mac / Windows）

Mac

  1. 公式ダウンロードページの「Proxyman for macOS」から dmg を入手します。Homebrew を使う場合は brew install --cask proxyman（公式 GitHub README に記載）。
  2. dmg を開き、Proxyman をアプリケーションフォルダに入れて起動します（一般的な手順）。
  3. 初回起動時に Proxyman Proxy Helper Tool のインストールを求められます。これはシステムプロキシを切り替えるための補助ツールで、入れないと通信を捕捉できません。公式：「At the first launch, Proxyman will present the Popup to install the Proxyman Proxy Helper Tool. You can skip it and install it later in Preference -> Advanced Tab.」
  4. 管理者権限のないユーザーは Helper Tool を入れないとシステムプロキシを切り替えられません。また、Proxyman の更新後に Helper Tool の再インストールを求められることがあります（公式）。

出典：Download ／ GitHub README（macOS） ／ Proxy Setting Tool

Windows

  1. 公式ダウンロードページの「Proxyman for Windows」からインストーラを入手し、実行します。
  2. Proxyman を起動します。Windows 版は起動中にシステムプロキシを自動で上書きします（公式 GitHub README：「automatically overriding the System Proxy」）。

出典：Download ／ GitHub README（Windows / Linux） ／ Windows 版 Changelog

2. ライセンスの有効化

当方からメールでお送りしたライセンスキーを、アプリに入力して有効化します。

Mac / Windows / Linux

  1. Proxyman を起動し、Proxyman Menu → Buy Proxyman Pro を開きます。
  2. Activate License ボタンを押し、ライセンスキーを入力します。

メニュー項目の名前は、公式の中でも表記が分かれています（有効化の手順では「Buy Proxyman Pro」、解除の手順では「Proxyman Pro…」、購入完了画面の案内では「Register License」）。ボタン名「Activate License」は、公式ドキュメントと公式スクリーンショット（macOS 版）で一致しています。Windows / Linux 版の画面は未確認です。

macOS ではコマンドでも有効化できます。アプリを /Applications に置き、1 回起動して終了してから実行します：/Applications/Proxyman.app/Contents/MacOS/proxyman-cli activate <ライセンスキー>

iOS / Android アプリ（Personal・Team のみ）

料金ページの比較表では、iOS / Android アプリは Personal と Team に含まれ、Standard には含まれません（ドキュメントの License ページにはプラン別の記載がありません）。

  • iOS：App Store から Proxyman for iOS を入れ、More タブ → Face ID & Passcode → Unlock → ライセンスキーを入力します。
  • Android：Google Play から Proxyman for Android を入れ、More タブ → Proxyman PRO → 一番下までスクロール → Unlock with desktop key → ライセンスキーを入力します。

1 シートで使えるモバイル端末の台数は、公式の記載が分かれています（ドキュメントは「1 seat can be activated on 2 iOS devices」、料金ページは「1 license seat can activate 1 iOS or Android device」）。Personal は料金ページで「up to 2 iOS or Android devices」です。

台数と端末の入れ替え

  • 同時に有効化できる台数は、Standard が 1 台、Personal が 2 台、Team が 1 シートにつき 1 台です（Mac・Windows・Linux のどれでも）。
  • PC を入れ替えるときは、古い端末で解除してから新しい端末で有効化します。macOS では Proxyman Menu → Proxyman Pro… → More → Revoke this Device… で解除します。Windows / Linux 版のアプリ内での解除方法は未確認です。
  • License Manager（https://proxyman.com/license-manager/access-link）でも解除できます。購入時のメールアドレスを入れて Send Access Link を押し、届いたリンク（7 日で失効）を開いて端末を削除します。ライセンスの登録メールアドレスが当方のままの場合、リンクは当方に届くので、端末の削除は当方にご依頼ください。

有効化できないとき

  • 社内プロキシがあると、ライセンスサーバーに届かず有効化できないことがあります。Tools → Proxy Settings → External Proxy Settings… で Enable External Proxy Tool にチェックを入れ、HTTP と HTTPS に社内プロキシのホストとポートを入れます。社内プロキシに認証がある場合は、ユーザー名とパスワードも入力します。そのあと、もう一度有効化します。公式の対応バージョンの記載は「macOS 5.5.0 以降」と「4.12.0 以降」の 2 通りあり、Windows / Linux で使えるかは未確認です。
  • 解決しない場合は contact@kiminori-kobo.com にご連絡ください。Proxyman のサポート（support@proxyman.com）へ英語で取り次ぎます。

3. 証明書の導入

HTTPS を復号するには、Proxyman が生成するルート証明書（Proxyman CA）を PC に入れて信頼させる必要があります。公式によれば、この証明書はお使いの PC 上で生成される自己署名証明書で、個人データを保存・送信することはありません。

Mac（Automatic Mode・推奨）

  1. Certificate メニューを開く
  2. Install a Certificate on this Mac... を選ぶ
  3. Automatic Mode で Mac のパスワードを入力する（Root Privileges）
  4. ボタンの表示が Installed & Trusted になったことを確認する

自動で入らない場合（Manual Mode）：同じダイアログの Manual タブ → Generate & Add（キーチェーンに追加されるが信頼はされない）→ キーチェーンの選択を求められたら System Keychain → キーチェーンアクセスで「Proxyman CA」を検索して開き、Always Trust（常に信頼） にして閉じる。

出典：Install Certificate on macOS

Windows（Automatic Mode・推奨）

  1. Certificate メニュー → Install Certificate on this Windows...
  2. Install & Trust をクリック
  3. システムのプロンプトで YES を選ぶ（裏では管理者権限で certutil -addstore "Root" <証明書のパス> が実行されます）

管理者権限がなくスクリプトを実行できない場合（Manual Mode）：Proxyman を終了 → C:\Users\<ユーザー名>\AppData\Roaming\Proxyman\certificate\certs\ca.cer を開く → Install Certificate → Current User → Place all certificates in the following store でストアを選ぶ（信頼されたルート証明機関） → Next → Finish → YES。

出典：Install Certificate on Windows

4. SSL Proxying の有効化

証明書を入れただけでは HTTPS は復号されません。復号したいドメインごとに SSL Proxying を有効にします。

  1. ブラウザなどで対象の HTTPS サイトに一度アクセスし、Proxyman の左パネルにドメインを表示させる
  2. 左パネルのアプリまたはドメインを右クリック → Enable SSL Proxying（公式：「Right-Click on the app or domain on the Left Panel -> Enable SSL Proxying」）。リクエスト一覧の行を右クリックしても同じ操作ができます
  3. ページを再読み込みし、リクエスト／レスポンスの中身が平文で表示されることを確認する
  • SSL Proxying List は ⌘⌥P で開けます（Mac）。Include List に入れたドメインを復号し、Exclude List に入れたドメインは無視します。
  • ワイルドカード：* はすべての HTTPS、*.example.com はサブドメイン、v?.example.com は 1 文字違いにマッチします。
  • macOS で HTTP/2 の通信を扱う場合は Settings の Use HTTP/2 を有効にします。

出典：SSL Proxying

5. iOS 実機の設定

前提：iPhone / iPad と PC が同じネットワークにあり、PC で Proxyman が起動していること。PC 側の証明書（第 3 節）を先に入れておきます。

  1. Proxyman の Certificate メニュー → Install Certificate on iOS → Physical Devices... でガイドを開く
  2. iOS の「設定」→「Wi-Fi」→ 接続中のネットワーク → HTTP プロキシを「手動」にし、サーバに PC の IP アドレス、ポートに 9090（Proxyman の既定ポート。アプリの表示で確認）、認証はオフ
  3. VPN アプリを使っていれば終了する（プロキシと競合します）
  4. Safari（プライベートタブ）で http://proxy.man/ssl または http://cert.proxyman.io を開き、プロファイルをダウンロードする。開けない場合は Wi-Fi に再接続し、Proxyman が起動しているか確認する
  5. 「設定」→「プロファイルがダウンロード済み」→ Proxyman CA → インストール（iOS 12.2 以降）
  6. 「設定」→「一般」→「情報」→ 証明書信頼設定（Certificate Trust Settings） で Proxyman CA をオンにする。プロファイルを入れただけでは信頼されません
  7. PC 側で対象ドメインの SSL Proxying を有効にし（第 4 節）、端末で通信して確認する
  • Flutter 製アプリはシステムプロキシを使わないため、アプリ側の HTTP クライアントにプロキシを設定する必要があります（公式）。
  • デバッグが終わったら iPhone から証明書を削除してください（公式の注意）。

出典：iOS Device

6. Android 実機の設定

  1. Proxyman の Certificate メニュー → Install Certificate on Android → Device でガイドを開く。PC 側の証明書（第 3 節）を先に入れておく
  2. Android の「設定」→ Wi-Fi → 接続中のネットワーク → プロキシを「手動」にし、ホストに PC の IP アドレス、ポートに 9090、認証なし
  3. 端末のブラウザで http://proxy.man/ssl または http://cert.proxyman.io を開いて証明書を入手する
    • Android 11 以降：Chrome でダウンロードしたあと、「設定」→「セキュリティ」→「暗号化と認証情報」→「証明書のインストール」→「CA 証明書」で Proxyman CA のファイルを選ぶ
    • Android 10 以前：自動でインストールされる。用途を聞かれたら「VPN とアプリ」を選ぶ
  4. Android 11 / 12 では「信頼できる認証情報」の「ユーザー」タブに Proxyman CA があることを確認する
  5. 自社アプリに設定を加える（Android 7 以降はユーザー証明書を既定で信頼しないため）：res/xml/network_security_config.xml にユーザー CA を信頼する設定（公式サンプルでは debug-overrides に user と system）を書き、AndroidManifest.xml の <application> に android:networkSecurityConfig="@xml/network_security_config" を追加する
  • リリースビルドからは network security config の緩和設定を外してください。本番の HTTPS 通信が傍受できる状態になります（公式の注意）。
  • VPN アプリは終了する。一部の Samsung 端末はプロキシ設定後にネットに出られなくなることがあり、ネットワークを削除して再接続します（公式）。
  • 他社製アプリ（証明書ピンニング等）は、この手順では復号できない場合があります。

出典：Android Device

7. Node.js / Python の通信を通す

Automatic Setup（推奨・macOS）

Proxyman v4.7.0 以降には、プロキシと証明書の設定済みターミナルを開く機能があります。Setup メニュー → Automatic Setup → Open New Terminal で開いたターミナルからスクリプトやサーバーを起動すると、その通信が Proxyman に表示されます。

  • Node.js：開いたターミナルで npm start などを実行する。
  • Python：requests、http.client、urllib3、httpx、aiohttp に対応と記載。開いたターミナルで python3 script.py を実行する。
  • 公式：「Only the pre-configured Terminal app is able to capture HTTP traffic out of the box」「It doesn't alter your bash_profile or zshrc file」。iTerm2 など別のターミナルを使う場合は Manual Setup を使います。
  • Automatic Setup の公式手順は macOS（Terminal.app）前提です。Windows 版での挙動は未確認です。

出典：Automatic Setup ／ NodeJS ／ Python

手動で設定する場合（公式は「not recommended」）

Node.js（axios 等）：Proxyman のステータスメニューに表示されるコマンドをターミナルで実行してから、同じターミナルでアプリを起動します。公式ドキュメントの例：

export https_proxy=http://192.168.1.103:9090 http_proxy=http://192.168.1.103:9090

node-fetch の場合は global-agent パッケージを使い、GLOBAL_AGENT_HTTP_PROXY=http://127.0.0.1:9090 を設定します。公式の例では NODE_TLS_REJECT_UNAUTHORIZED=0 で証明書検証を無効にしていますが、開発時以外は使わないでください。

Python（requests 等）：Mac に証明書を入れたうえで、証明書のパスを環境変数で渡します（公式の例）：

export SSL_CERT_FILE=~/.proxyman/proxyman-ca.pem
export REQUESTS_CA_BUNDLE=~/.proxyman/proxyman-ca.pem

出典：NodeJS ／ Python

9. 使い終わったら（証明書の削除）

  • Mac：Certificate メニュー → Reset all Certificates → Mac のパスワードを入力。公式は、Proxyman を使わなくなったらキーチェーンから Proxyman の証明書を削除するよう注意しています（証明書を持つ者が Mac の通信を傍受できるため）。
  • iOS / Android：端末に入れた Proxyman CA を削除し、Wi-Fi のプロキシ設定を元に戻す。
  • Android アプリ：リリースビルドから network security config の緩和設定を外す。

出典：Install Certificate on macOS ／ iOS Device ／ Android Device
